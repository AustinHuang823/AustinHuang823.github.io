XtalPi · Development, test & deployment teams

AI Operations Platform for Robotic Automation

One shared operations layer for robotic lab automation: monitor runs, diagnose faults, keep failures from repeating, prepare tests, and share what teams learn

Shared operational context for LLM agents. The platform puts robot telemetry, process records, logs, device configs, and engineering knowledge behind one governed data plane, so agents can say where a run stands, triage a fault against a reviewed incident casebook, trace the root cause afterward, and catch config drift before the next run. Every answer cites its source.

Inside the system

Live operations visibility. Ask where a run stands and get per-module progress and the latest results. ETA forecasts follow the workflow's dependency graph and are scored later against what actually happened; scheduled briefings roll status, resources, and drift into one page.

Diagnosis and root-cause analysis. Live triage matches a fault to past incidents and pulls the logs, drive state, and process records around it. After a run, agents link errors to steps, trace stalled workflows to the resource or lock that blocks them, and break down calibration, motion, and cycle-time problems.

Prevention and change control. Config-drift detection against an approved baseline, regression checks after upgrades, pre-run rules drawn from past incidents, and code-change review that ends in a patch an engineer applies.

Test and run preparation. Leveled test plans, from a single operation to a full workflow, and material feed plans with step-by-step loading guidance.

Knowledge that builds up. Each understood incident becomes a fingerprinted case that engineers review, every diagnosis starts by checking those cases, and recurring failures can be promoted into pre-run rules. Questions about team docs get answers with citations.

A platform teams build on. Teams install it themselves, and engineers outside the core project have built chat bots on the same capability layer for error analysis, status tracking, and reports. A new site is a configuration change, not a code change.

Production software. 50+ capabilities over 10+ data-source types, 1,700+ automated tests at about 90% coverage, strict typing, and 17 quality gates on every commit. Database access is read-only through named queries, and anything that acts on hardware needs explicit confirmation.

04 — About

From welding torches to vision pipelines

I started in mechanical engineering at National Taiwan University, then spent my early career with my hands on hardware — building a combat robot for a streaming series that surpassed one billion cumulative views and engineering surgical camera systems that had to survive drops, dust, and operating rooms.

After national service in Taiwan, I went back to school to close the loop between mechanism and intelligence, earning my M.S.E. in Robotics at Johns Hopkins (GPA 3.9) while working on medical robotics under Russell H. Taylor and lab automation at the NIH.

Today at XtalPi I'm the primary technical owner for automation across U.S. operations, taking robotic systems from lab demos to production floors, where a robot that "usually works" isn't good enough.

I also lead the AI operations platform that turns what our robots, runs, and engineers know into shared context for LLM agents, so that knowledge stops living in a few people's heads. New engineers get up to speed within a week, operators get answers without paging an engineer, teams across time zones work from the same picture instead of waiting overnight, and leads can read risk from recent errors before setting the next timeline.

I build with AI the way I build robots: orchestrated multi-agent development workflows, where parallel branches pass cross-model review gates, strict typing, and enforced test coverage before anything merges. It's the same discipline I bring to hardware, applied to the agents that help run it.

The common thread: I'm happiest at the boundary where mechanical design, perception, software, and AI meet — and I've shipped work in all four.
